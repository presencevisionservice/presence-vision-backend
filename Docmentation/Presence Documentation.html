Frontend Integration Note: Presence uses stateless JWT authentication, but tokens are transported exclusively through HttpOnly cookies (access and refresh). Clients (Axios, Fetch) must send withCredentials: true on every request so the browser attaches cookies automatically. Never extract tokens manually or store them in localStorage.

Base URL

Every endpoint documented on this page — in both Part 01 and Part 02 — is relative to a single base API URL. Prefix all paths below with it.

BASE https://presence-backend-hnix.onrender.com

Configuring a Client

JavaScript · Axios Recommended 
const BASE_URL = "https://presence-backend-hnix.onrender.com";

axios.defaults.baseURL = BASE_URL;
axios.defaults.withCredentials = true;
Fetch
fetch(`${BASE_URL}/authentication/user_login`, {
  method: "POST",
  credentials: "include",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(payload)
});

Environments

  • Production https
    https://presence-backend-hnix.onrender.com
  • Staging https
    https://staging-api.presence.app
  • Local development http
    http://127.0.0.1:8000

Cookies are issued with Secure and SameSite attributes, so cross-origin requests require HTTPS plus the correct CORS credentials configuration on the server.

01

Authentication

Identity, sessions, two-factor security and account recovery.

User Registration

Registers a new user and triggers an OTP email for account verification.

POST https://presence-backend-hnix.onrender.com/authentication/user_registration

Request Body

  • email string (required)
    User's valid email address.
  • username string (required)
    Unique account username.
  • password string (required)
    Secure password string.

Responses

201 Created Success 
{
  "verification_token": "xyz123_url_safe_token"
}
400 Bad Request Error 
{
  "error": "Email already exists."
}

Verify Account OTP

Activates a newly registered account and sets HttpOnly session cookies upon success. Includes a rate limit of 5 attempts per 15 minutes.

POST https://presence-backend-hnix.onrender.com/authentication/user_otp_verify

Request Body

  • verification_token string (required)
    Token returned from the registration step.
  • otp string (required)
    4-digit code sent to user email.

Responses

200 OK Sets access & refresh cookies 
{
  "msg": "OTP Verified, User is Now Active",
  "store_date": "2026-09-29",
  "store_time": "12:50:07"
}
429 Too Many Requests Rate Limited 
{
  "error": "Too many Verification Requests. Try Again Later"
}

User Login

Authenticates standard credentials. If 2FA is off, issues cookies immediately. If 2FA is on, redirects to PIN challenge. Max 5 attempts per 15 minutes.

POST https://presence-backend-hnix.onrender.com/authentication/user_login

Request Body

  • email string (required)
  • password string (required)

Responses

200 OK (Standard Login) Sets cookies 
{
  "msg": "Login Successful"
}
200 OK (2FA Enabled) Requires PIN routing 
{
  "is_restricted_account": true,
  "email": "user@domain.com"
}

User Logout

Blacklists the current refresh token and deletes access and refresh cookies from the client browser. Requires active session.

POST https://presence-backend-hnix.onrender.com/authentication/user_logout

Headers

Browser must pass the refresh cookie natively via withCredentials.

Responses

200 OK Cookies deleted 
{
  "msg": "Logout Success"
}

Refresh Tokens

Evaluates the refresh cookie. If nearing expiration (within 50 minutes of end-life), rotates both access and refresh cookies. Otherwise, rotates only the access cookie (10 min expiry).

GET https://presence-backend-hnix.onrender.com/authentication/refresh_user_tokens

Requirements

Requires active refresh cookie. Endpoint is open (AllowAny) but will fail without the cookie.

Responses

200 OK (Rotated Access Only) Updated 
{
  "msg": "Updated Access Token"
}
401 Unauthorized Expired 
"Refresh Token Expired. Please Login Again"

Google OAuth Flow

Handles seamless third-party login via Google.

GET https://presence-backend-hnix.onrender.com/authentication/login/google/

Step 1: Redirect the user's browser to this endpoint. It dynamically builds the Google Consent Screen URL and redirects the client.

GET https://presence-backend-hnix.onrender.com/authentication/callback/google/

Step 2: Handled by Backend. Google returns the authorization code here, backend creates/finds the user, then redirects back to the frontend UI appending ?verification_token=... to the URL.

GET https://presence-backend-hnix.onrender.com/authentication/get_authorization_tokens/<verification_token>

Step 3: Front-end intercepts the token from the URL params and calls this endpoint to trade it for secure HttpOnly cookies.

02

API

Core Presence resources, conventions and endpoint reference.

API Overview & Conventions

Every endpoint in Part 02 shares the same base URL, the same cookie-based authentication model and the same response envelope as Part 01. The rules below apply to all requests.

BASE https://presence-backend-hnix.onrender.com/api/v1

Request Conventions

  • Content-Type header
    Always application/json for POST, PUT and PATCH bodies.
  • Accept header
    Send application/json.
  • Credentials client config
    Set withCredentials: true so the access cookie is attached automatically.
  • Versioning path prefix
    Core resources live under /api/v1/. Auth endpoints are unversioned.

Response Envelope

200 OK Success 
{
  "success": true,
  "data": { ... },
  "meta": {
    "request_id": "req_8f2c1a"
  }
}

Endpoints that return a single primitive (for example a status string) may bypass the envelope.

Errors, Pagination & Rate Limits

Consistent error shapes and list behaviour across all Presence resources.

Error Shape

400 Bad Request Error 
{
  "success": false,
  "error": {
    "code": "validation_error",
    "message": "Field 'email' is required.",
    "fields": { "email": ["This field is required."] }
  }
}

Status Codes

  • 200 OK
    Request succeeded.
  • 201 Created
    Resource created.
  • 400 Bad Request
    Validation failed.
  • 401 Unauthorized
    Missing or expired access cookie — call the refresh endpoint.
  • 403 Forbidden
    Authenticated but lacking permission.
  • 404 Not Found
    Resource does not exist.
  • 429 Too Many Requests
    Rate limit exceeded — back off and retry.
  • 500 Server Error
    Unexpected server failure.

Pagination

List endpoints accept page and page_size query parameters and return a paginated envelope.

200 OK
{
  "count": 128,
  "next": ".../resources?page=3",
  "previous": ".../resources?page=1",
  "results": [ { ... }, { ... } ]
}
  • page integer
    1-based page number. Default 1.
  • page_size integer
    Items per page. Default 20, max 100.

Rate Limits

Sensitive authentication endpoints are throttled (for example 5 requests / 15 minutes). When exceeded the API responds with 429 Too Many Requests. Inspect the Retry-After response header before retrying.

List Resources

Returns a paginated collection of Presence resources belonging to the authenticated user.

GET https://presence-backend-hnix.onrender.com/api/v1/resources

Query Parameters

  • page integer
    Page number, 1-based.
  • page_size integer
    Items per page (max 100).
  • search string
    Optional free-text filter.
  • ordering string
    Field to sort by. Prefix with - for descending.

Requires active access cookie.

Responses

200 OKPaginated
{
  "count": 128,
  "next": ".../resources?page=2",
  "previous": null,
  "results": [
    {
      "id": "res_01H9...",
      "name": "Example",
      "created_at": "2026-09-29T12:50:07Z"
    }
  ]
}
401 UnauthorizedExpired
{
  "success": false,
  "error": {
    "code": "token_not_valid",
    "message": "Access token expired."
  }
}
